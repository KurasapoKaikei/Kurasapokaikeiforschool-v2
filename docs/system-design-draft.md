# クラサポ会計 for school システム設計書（草案）

**文書の位置づけ**  
本書は、現時点の開発状況を一般の担当者向けに整理した**草案**である。用語の定義、画面名、数値例は今後、公式な運用指針と突き合わせて改訂する。

---

## 1. プロジェクト概要

### 1.1 システムの目的

**クラサポ会計**は、部活動やサークルに付随する会計を、紙台帳やバラバラな表計算に頼らず、**一つのWebアプリケーション**の中で、入力・集計・照合・報告の流れをつなぎ、透明性の高い運用を目指すものである。「クラサポ会計 **for school**」は、特に**学校（大学等）**と**部・クラブ**、**保護者**の三者が会計プロセス上で噛み合うことを想起したラインアップ名として位置づけられる。現状、単一クラブ内での運用を中心とした「クラブ会計用ソフト」としての機能群が実装されつつあり、**学校用の一括制御**や**保護者専用アプリ**の全体は、段階的に拡張する前提である。

### 1.2 想定する三つの立場

本草案では、利用者像を次の三つに大別して説明する。実装では、ログイン形態と権限名を、**データベース**（情報を束ねる台帳のような格納先）上の**ロール**、すなわち「役割」として定義し、画面操作や、サーバーと画面の**やり取り**（Web 経由の要求と応答）の扱いに対応づけている。

**（1）学校（母組織）**  
大学や高校など、複数のクラブを置く**上位の組織**を想定する。将来、全校横断の監査、クラブ横断の提出ルール、契約上の**カスタマイズ制限**（例：部独自の会計枠の固定）などの起点となる。学校契約向けの画面では、クラブ名などの**一部の設定欄を編集不能**にする、といった制御が想定されており、システム内では「**学校向け**」かどうかのフラグで挙動を切り替えられる土台を用意する。

**（2）クラブ会計（部の担当者）**  
日々の**入出金登録、集金、帳票閲覧、予算の入力、収支の説明**を行う、いわゆる**部の会計責任者**である。内部実装上は**クラブ管理者**ロールがこれに当たる。会計期間中の取引、予算行の登録、年度末前の**報告上の下書き**は原則ここで行う。クラブ会計の操作が、後述の**会計年度のロック**と整合する形で、データベースに反映される。

**（3）保護者**  
保護者自身が本システムの「フル画面」にログインする、という形だけを想定するのではなく、**児童・生徒の納付状況の閲覧**や、将来の**決済の通知**の受信先、といった、**会計事実の外側**の利用者像として位置づける。従来仕様では、**トークン付きの専用URL**（ログイン不要）で、当該部員の集金名・金額・入金状況だけを**閲覧専用**に見せる、といった導線が定義されており、**完全な会計帳票の改ざん防止**はクラブ会計と学校のプロセスに委ねる、という分担になる。

## 2. 画面・UI仕様

### 2.1 全体的なデザインの考え方

各機能エリア（マイページ、入出金、帳簿、集金、設定など）には、**区別のしやすいテーマ色**（ピンク、黄緑、青緑、オレンジ、水色、パープル等）を割り当て、サイドメニューと**画面上部のテーマ帯**で「今どの仕事の画面か」が一瞬で分かるようにする。

そのうえで、**予実管理**（予算と実績の管理）のまとまり（モジュール）には、**ディープ・インディゴブルー**（**濃い紺色**、デザイン指定では **#1A237E**）を主色とし、**他の帳票画面（収支報告書など）と同じ**「ベージュ系の地」に**白のカード**を載せ、カード先頭左に**細い紺色のライン**を入れる、という合わせ方で統一する。文字は見出しは紺、本文は**グレー系**で、数字は右寄せ・カンマ区切り、単位「円」は帳表の見出し付近にまとめて示す、といった**帳票っぽい**ルールに沿う。

### 2.2 二段構成の「ヘッダー」

**一段目**は、全ページ共通の**グローバルヘッダ**の、クラブ名・会計期間の行の**すぐ下**に来る、**色付きの横長の帯**である。予実管理の下位画面にいるときは、この帯の背景色が上記の**インディゴ**になり、**白抜きの太い文字**で**「予実管理」**とだけ表示する。いわば「**今いる大見出しの本棚**」のラベルである。

**二段目**は、そのすぐ下の**同じ作業欄**の中に置く、**白背景**の**見出しブロック**である。左端に**一本だけ濃い紺**の太線（**左アクセント**）を付け、**太字の紺**で、画面ごとの**小見出し**（例：**「予算書」**、**「前年度比」**）を書く。一行目はグレーで補足（年度・カテゴリの説明・単位等）を書き、**古い二重枠**や、内側の**別色の飾り付き**は置かない。

この二段（大見出しの色帯＋白抜きの小見出し）が、**予実管理**の画面で一連の**「帳票ページと同型」**の顔立ちになる。必要に応じて、二段目の**さらに下**に、カテゴリ切替用の**タブ**を並べ、帳表本体は**その下の大きい白枠**に入れる、という**三段までの縦積み**にする。ここは**集計帳**と同じ「上が説明、下が表」の印象を与える。

### 2.3 実装されている主要な画面の役割

**マイページ**  
会計期間中の**資産・負債の概況、お知らせ、要対応の通知、部員数**などを一画面で把握する。入口としての**ダッシュボード**である。

**入出金登録**  
**収入・支出・振替・集金・繰延**など、日常の**仕訳**を入力する。左右分割や一列の切替で、**証憑画像**（レシート等）の確認と併用できる。学校契約下では、**クラブ名など一部設定の変更**が制限されうる、という整理がある。

**予実管理（予算書）**  
**年度の予定額（予算）**を、**カテゴリー**（部会計、合宿会計、遠征費等）**ごと**に、科目行へ入力し、**入出金の実績**と並べて**差額・達成率**を見る。全カテゴリーを束ねた**集計**も見る。

**予実管理（前年度比）**  
**一つ前の年度**と**今年度**の、同一科目上の**実績**を並べ、**増減額と増減率**を見る。予算行は使わず、**実績同士**の比較が主である。

**収支報告書**  
年度内の**収入の部**と**支出の部**を、**表形式**でまとめ、備考欄付きの**定型的な帳票**として画面に出し、**印刷想定**の体裁に合わせる。予実管理の**白帯＋表**の**語彙**と揃える。

## 3. 予実管理のロジック仕様

### 3.1 カテゴリー別の入力と「すべて」

**予算**は、**会計年度**、**カテゴリー**、**勘定科目**（会費収入、遠征費など）の**三つの組**で一つの数が決まる。利用者は画面上部の**タブ**で、**特定の一つのカテゴリー**、または**「すべて」**を選べる。

**特定のカテゴリーを選んだ場合**、そのカテゴリーに**紐づく科目**だけが行として見え、**予算欄**は**そのカテゴリーに対する数**を**キーボードで入力**し、**入力欄からフォーカスを外す**（別の欄を押す、タブ移動する等）と、**一時的な下書き**から**正式な登録**へ回す。同じ科目でもカテゴリーが違えば、予算額の箱は**別**である。

**「すべて」を選んだ場合**、画面は**全カテゴリーを一つの帳**として見るモードになる。**予算**は、同じ**科目**について、**各カテゴリーの予算**を**足し上げた合計**を表示する（保存されているカテゴリー別の数を上から**集計**する）。このモードでは、**一つの大きい数を直接打ち直す**のではなく、**中身はカテゴリー別**に保持されたまま、**合計の見方**に切り替わる。文言上は**閲覧専用**の**集計**として扱い、**年度予算額**のセルは**数値表示のみ**とし、**個別のカテゴリータブ**に移ると、そこで**再び入力**できる。実務のイメージは、「**合計レポート用のビュー**」と「**部門の担当者が数字を入れる画面**」の切替である。

### 3.2 予算額、実績額、差額、達成率

**実績額**は、**入出金の登録データ**と、**集金から自動でつながる入金**などを、**当該会計年度**の期間内に**発生したもの**だけに**絞り**、**カテゴリー名と科目名**の**組**ごとに**足し上げ**たものを使う。通帳の**振替**や**支出**も、**科目とカテゴリー**のラベルが一致する行を集めて加算する。

**差額**は、**科目と収入か支出の区分**に応じて、次の考え方を採用する。  
- **収入**では、**実績額**から**予算額**を**引き**、**黒字寄り**がプラス、という**残り**を差額とする。  
- **支出**では、**予算額**から**実績額**を**引き**、**使い道が予定より減る**とプラス、**使いすぎ**だと負、という、**枠の中にどれだけ残るか**の**残り**を差額とする。

**収支合算**（収入と支出の差し引き等）の**予算同士・実績同士**の比較も、**同じ帳**の**合計行**で**一貫**して扱う。

**達成率**は、**予算がゼロでない**とき、**実績を予算に対する**割合で表す。前年度比の画面では、**前年度**と**今年度**の**実績**だけの比較とし、**差**は**今年度**から**前年度**を**引いた**増減額、**率**は**前年度**を**分母**にした**変化**として示す。データが**ない**年は、**比較不能**の説明（ゼロ表示や注意書き）に寄せる。

## 4. 権限とデータの整合性（現状の想定）

### 4.1 クラブ管理者（会計上の主担当者）の役割

**クラブ管理者**は、日々の取引の登録・修正、予算行の更新、集金の実績登録、帳票の作成と説明を担う。システム内部では、他のロール（例：大学全体の管理者、顧問に相当する監査、学生部員）と区別し、承認者と入力者を将来の承認フローに載せる前提が置かれている。本草案執筆時点の画面では、部の会計実務の中心となる担当者＝クラブ管理者、と理解すれば足りる。

**補足（表記上の揃え）**  
社外説明で「部管理者」、社内や設計図面で英略称 CLUB_ADMIN などを使うことがある。いずれも本システムのデータ上はクラブ管理者ロールとして同一の担当者像を指す、という扱いでよい。

### 4.2 会計年度の「締まり」とロック（提出・承認と編集不可）

会計年度（例：4月始まりの一年区切り）には、次の三つの**業務ステータス**（進み具合のラベル）で骨格を置いている。

- **下書き（編集中）**  
  取引も予算も、足したり直したりできる。

- **提出済み**  
  学校等へ報告書を提出したあとの状態。いわば、学校へ出した提出資料に、後から無断で行を足さない、という段階に相当する。

- **承認済み**  
  学校側で了承を得たあとの状態。

提出済みまたは承認済みの年度は、すでに固まった帳として扱い、システム上の「ロック」と同じ意味にまとめている。当該年度の新しい入出金の追記、古い行の削除、予算の数値の書き換えは、原則拒否する。予算の保存をサーバーに送る手続（Web のサーバー向け受付）の段階で、年度の状態を調べ、ロックなら「この年度は変更できません」と返す。データベースに保存する内容と、ブラウザ内の仮のメモ欄（一時的な下書き）の扱いを、運用で揃えていくことが重要である。

報告書そのものを一画面にまとめるかどうかにかかわらず、上記の年度ステータスが、帳表の締切という運用上の事実に対応する、という合意づくりの前提に置いている。

## 5. 今後の拡張の展望

**保護者向けの専用アプリ（クラサポ会計ブランド）との連携**  
トークン付きの閲覧用 URL を足がかりに、通知による納入の催促、子ども一人ひとりに沿った表示の一貫、本人確認（二段階認証など）の強化、といった、学校とクラブの「あいだ」に立つ会計外の体験を拡充する想定である。

**オンライン決済**  
部費・遠征の徴収を、クレジットカードや口座振替などから会計上の仕訳へ直接つなぎ、同じ入金を人の手で二重に拾わない、という目標。

**自動消込・照合**  
入金と、集金の予定や仮受金の予定などの紐づけ作業を、ルール化と、必要に応じた知能的な補助の両方で減らす。あわせて、同額の重複や不自然な行を、人の審査の前に示す、といった方向性。
